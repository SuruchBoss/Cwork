# ติดตั้ง Cwork บน NAS (Synology) รายการตรวจสำหรับผู้ติดตั้ง

คู่มือนี้พาติดตั้ง Cwork บน NAS ที่ออฟฟิศมีอยู่แล้ว (เช่นเครื่องที่รัน Odoo อยู่) ให้พนักงาน HR เปิดใช้ผ่านเบราว์เซอร์ในออฟฟิศเท่านั้น
ไม่เปิดออกอินเทอร์เน็ต ไม่ต้องใช้คีย์หรือสมัครสมาชิกใดๆ ทั้งการติดตั้ง การอัปเดต และการสำรองข้อมูล

**สถานะของคู่มือ:** ขั้นที่ทำบนหน้าจอ DSM (Package Center, Task Scheduler, ไฟร์วอลล์) ยังไม่ได้ลองบน Synology จริง
เขียนจากที่ซ้อมบนเครื่อง Docker ธรรมดา ผลการซ้อมอยู่ที่ `docs/nas-rehearsal-2026-10.md` ครั้งแรกที่ทำบนเครื่องจริง
ให้จดสิ่งที่ต่างจากคู่มือแล้วแจ้งผู้พัฒนา และ **ห้ามทำบน NAS ของบริษัทจนกว่าเจ้าของบริษัทอนุญาต**

ผู้ติดตั้งต้องพิมพ์คำสั่งผ่าน SSH ได้ ถ้าไม่เคยทำ ให้ทำกับคนที่ดูแลไอทีของบริษัท

## ก่อนเริ่ม

- [ ] เจ้าของบริษัทอนุญาตให้ติดตั้งแล้ว
- [ ] สำรอง Odoo ล่าสุดไว้แล้ว (ติดตั้ง Cwork ไม่แตะ Odoo แต่ต้องมีที่ย้อนกลับ) และเลือกเวลาที่ไม่มีใครทำงานบน Odoo
- [ ] NAS เป็น DSM 7.2 ขึ้นไป (Control Panel → Info Center)
- [ ] เปิด SSH ใน DSM แล้ว (Control Panel → Terminal & SNMP) และมีบัญชีผู้ดูแลระบบ
- [ ] ที่อยู่ของ NAS ในเครือข่ายออฟฟิศเป็น **ที่อยู่คงที่** (ตั้งจอง IP ที่เราเตอร์ ถ้าที่อยู่เปลี่ยน ทุกเครื่องจะเข้า Cwork ไม่ได้จนกว่าจะแก้)
- [ ] มี **USB drive หรือเครื่องอื่น** สำหรับเก็บสำรองข้อมูล ไม่ใช่ดิสก์ลูกเดียวกับที่ NAS ใช้เก็บ Cwork
- [ ] มีที่เก็บรหัสผ่านที่ปลอดภัย (เช่นโปรแกรมจัดการรหัสผ่าน) สำหรับเก็บ **คีย์เข้ารหัส**
- [ ] ได้โฟลเดอร์ `deploy/nas` ของ Cwork (ถ้าไม่มีอินเทอร์เน็ตบน NAS ต้องมีไฟล์ `images.tar.gz` และ `images.version` ในโฟลเดอร์นั้นด้วย) ก๊อปไปไว้ใน NAS เช่น `/volume1/docker/cwork/`

## ขั้นที่ 1 เช็กเครื่อง (ไม่เปลี่ยนอะไรเลย)

เข้า SSH แล้วพิมพ์

```
sudo -i
cd /volume1/docker/cwork/deploy/nas
./check.sh
```

อ่านบรรทัดสุดท้าย

- **PATH A** ไปขั้นที่ 3
- **PATH B** ยังไม่มี Container Manager ไปขั้นที่ 2
- มีบรรทัด `[FAIL]` แก้ตามที่เขียนก่อน (เช่นหน่วยความจำหรือพื้นที่ว่างไม่พอ) แล้วรันใหม่

## ขั้นที่ 2 ติดตั้ง Container Manager (เฉพาะ PATH B)

DSM → Package Center → ค้นหา **Container Manager** → ติดตั้ง แล้วกลับไปรัน `./check.sh` ใหม่ ต้องได้ PATH A

## ขั้นที่ 3 ติดตั้ง Cwork

```
./install.sh --backup-dir /volumeUSB1/usbshare/cwork-backup
```

ใส่ที่อยู่โฟลเดอร์ของ USB drive ของจริงแทนตัวอย่าง ถ้าที่ตรงนั้นไม่มี (ยังไม่เสียบไดรฟ์) ตัวติดตั้งจะบอกตอนสำรองข้อมูล ไม่ใช่ตอนนี้

ตัวติดตั้งจะถามยืนยันที่อยู่ที่พนักงานจะพิมพ์ ตอบ `y` ถ้าถูก รอจนขึ้น `Cwork is running` (ครั้งแรกอาจนาน ถ้ามีไฟล์ `images.tar.gz` จะเร็วกว่า)
เครื่อง NAS จะเปิดพอร์ตเดียวคือ **8443** ถ้าพอร์ตนี้ชนกับของอื่น ใส่ `--port 9443` (หรือเลขอื่น) ต่อท้าย

## ขั้นที่ 4 สร้างผู้ดูแลคนแรก และเก็บคีย์เข้ารหัส

```
./first-admin.sh --web
```

จะได้ **โทเค็น** (ใช้ได้ครั้งเดียว หมดอายุใน 1 ชั่วโมง) กับที่อยู่ `https://...:8443/setup` เปิดที่อยู่นั้นในเบราว์เซอร์ ใส่โทเค็น
ชื่อองค์กร อีเมลและรหัสผ่านผู้ดูแล โทเค็นนี้สร้างผู้ดูแลที่มีสิทธิ์ทุกอย่างได้ อย่าส่งในแชท

แล้วรัน

```
./show-key.sh
```

**ก๊อปคีย์ที่ขึ้นไปเก็บในที่เก็บรหัสผ่านทันที** เลขบัตรประชาชนและบัญชีธนาคารของพนักงานเข้ารหัสด้วยคีย์นี้
**ถ้าคีย์หาย ข้อมูลเหล่านั้นอ่านไม่ได้ตลอดไป** ไม่มีทางกู้ ห้ามเก็บคีย์ไว้ในโฟลเดอร์เดียวกับไฟล์สำรอง

## ขั้นที่ 5 ให้เครื่องในออฟฟิศเชื่อใจ HTTPS

Cwork ออกใบรับรองของตัวเอง เบราว์เซอร์จึงเตือนจนกว่าจะเชื่อใจใบรับรองนี้ **ทำครั้งเดียวต่อเครื่อง**

บน NAS รัน `./export-ca.sh` จะได้ไฟล์ `cwork-office-ca.crt` กับ **ลายนิ้วมือ (fingerprint)** ที่พิมพ์ออกมา
ก๊อปไฟล์ไปที่เครื่องพนักงาน (USB หรือโฟลเดอร์แชร์) แล้ว

1. ดับเบิลคลิกไฟล์ → **Install Certificate**
2. เลือก **Local Machine** → ถ้ามีหน้าต่างถาม ให้กด Yes
3. เลือก **Place all certificates in the following store** → Browse → **Trusted Root Certification Authorities**
4. Next → Finish ปิดเบราว์เซอร์แล้วเปิดใหม่
5. เปิด `https://<ที่อยู่ NAS>:8443` ต้องไม่มีคำเตือน และต้องพิมพ์ **ที่อยู่เดียวกับที่ตั้งตอนติดตั้งเท่านั้น** ถ้าพิมพ์เป็นชื่ออื่นหรือที่อยู่อื่น เบราว์เซอร์จะเตือน

เทียบลายนิ้วมือที่เครื่องพนักงาน (ดูรายละเอียดของใบรับรอง) กับที่พิมพ์บน NAS ว่าตรงกัน ขั้นนี้ยังไม่ได้ลองบน Windows จริง

## ขั้นที่ 6 ตั้งสำรองข้อมูลทุกคืน

1. เสียบ USB drive แล้วดูว่า DSM เห็นที่โฟลเดอร์ใด (File Station)
2. เปิด `.env` (`vi .env` หรือแก้ใน File Station) ให้ `CWORK_BACKUP_DIR=` ชี้โฟลเดอร์บน USB drive
3. รันครั้งแรกด้วยมือ `./backup.sh` ต้องขึ้น `Backup: ...` ถ้าขึ้นว่าอยู่ดิสก์เดียวกัน แปลว่าเลือกที่ผิด (นั่นคือสิ่งที่ตั้งใจ ระบบไม่ยอมสำรองลงดิสก์เดียวกับข้อมูล)
4. DSM → Control Panel → **Task Scheduler** → Create → Scheduled Task → **User-defined script**
   ผู้ใช้ **root** ทุกวัน เวลาตอนไม่มีคนใช้ ในช่อง script ใส่

   ```
   cd /volume1/docker/cwork/deploy/nas && ./backup.sh
   ```

5. **เช้าวันถัดไปไปดูโฟลเดอร์** ว่ามีไฟล์ใหม่จริง ขั้นนี้ยังไม่ได้ลองบน Synology จริง

ระบบเก็บสำรอง 14 วัน ไฟล์เก่ากว่านั้นถูกลบเอง ไฟล์ `.sql.gz` คือฐานข้อมูล ไฟล์ `.uploads.tar.gz` คือไฟล์ที่แนบ

## ขั้นที่ 7 ทดสอบกู้คืนหนึ่งครั้งก่อนใช้จริง

สำรองที่ไม่เคยทดสอบกู้ ยังไม่ถือว่ามีสำรอง ให้ทดสอบตอนที่ยังไม่มีข้อมูลจริง

```
./restore.sh /ที่อยู่/cwork-วันที่-เวลา.sql.gz
```

พิมพ์ `RESTORE` เมื่อถาม สคริปต์จะลองคีย์กับไฟล์สำรองก่อน ถ้าคีย์ไม่ตรงจะหยุดโดยไม่แตะข้อมูลจริง แล้วเข้าสู่ระบบอีกครั้งดูว่าข้อมูลกลับมา

## ปัญหาที่เจอบ่อย

| อาการ | สาเหตุที่น่าจะเป็น |
|---|---|
| เบราว์เซอร์เตือนใบรับรอง | พิมพ์ที่อยู่ไม่ตรงกับที่ตั้งตอนติดตั้ง หรือเครื่องนี้ยังไม่ได้ติดตั้งใบรับรอง (ขั้นที่ 5) |
| `check.sh` บอกหน่วยความจำไม่พอ | มี container อื่นใช้เยอะ Cwork ต้องการว่างราว 1.5 GB |
| สำรองข้อมูลไม่ยอมทำ | โฟลเดอร์อยู่ดิสก์เดียวกับข้อมูล หรือยังไม่ได้เสียบ USB drive |
| เข้าสู่ระบบแล้วขึ้นข้อผิดพลาดหลังกู้คืน | คีย์ใน `.env` ไม่ใช่คีย์ที่ใช้ตอนทำสำรอง ใส่คีย์ที่เก็บไว้แล้วกู้ใหม่ |
| ที่อยู่ของ NAS เปลี่ยน | จอง IP ให้ NAS แล้วติดตั้งใหม่หรือแก้ `CWORK_HOST` และ `PUBLIC_WEB_URL` ใน `.env` แล้ว `./export-ca.sh` ให้ทุกเครื่องเชื่อใจใบรับรองใหม่ |

ดูสถานะ `./status.sh` ดูบันทึกการทำงาน `docker logs cwork-api-1`

## อัปเดตเวอร์ชัน และย้อนกลับ

1. วางโฟลเดอร์ `deploy/nas` เวอร์ชันใหม่ทับของเดิม **โดยไม่ลบไฟล์ `.env`** (มีรหัสลับ ไม่ใช่ไฟล์ที่ส่งมากับเวอร์ชันใหม่)
2. `./update.sh` สคริปต์จะสำรองข้อมูลก่อนเสมอ ถ้าสำรองไม่ได้ จะไม่อัปเดต
3. ถ้าอัปเดตแล้วมีอะไรผิดปกติ `./rollback.sh` กลับไปเวอร์ชันและข้อมูลก่อนอัปเดต
   ข้อมูลที่พนักงานกรอกหลังอัปเดตจะไม่อยู่ในไฟล์สำรองนั้น ระบบจะสำรองสถานะปัจจุบันไว้ให้ก่อนกู้ (ชื่อไฟล์มี `before-restore`)

## ลบ Cwork ออกจากเครื่อง

`./uninstall.sh` **ลบฐานข้อมูลและไฟล์แนบทั้งหมด** ต้องพิมพ์ `ERASE` ไฟล์สำรองในโฟลเดอร์สำรองไม่ถูกแตะ คีย์ใน `.env` หายไปพร้อม `.env` ต้องเก็บคีย์ไว้ก่อนถ้าอาจต้องกู้ภายหลัง

## ทางเลือกสุดท้าย: ข้อมูลอยู่ NAS แอปอยู่ PC (path C)

ใช้เมื่อ NAS รันทั้งชุดไม่ไหวเท่านั้น (ยังต้องมี Container Manager บน NAS เพราะฐานข้อมูลรันเป็น container)
ติดตั้ง `./install.sh --mode db` บน NAS แล้ว `./install.sh --mode app --host <ที่อยู่ PC> --db-host <ที่อยู่ NAS> --db-password <รหัสจาก .env บน NAS>` บน PC ที่มี Docker
ข้อควรรู้ ฐานข้อมูลเปิดบนเครือข่ายออฟฟิศ (พอร์ต 5432 ไม่เข้ารหัส) ให้ตั้งไฟร์วอลล์ NAS อนุญาตเฉพาะที่อยู่ของ PC เครื่องนั้น
PC ต้องเปิดอยู่ตลอดเวลาที่ HR ทำงาน และต้องสำรองข้อมูลทั้งสองเครื่อง รายละเอียดอยู่ใน `docs/operations.md`
