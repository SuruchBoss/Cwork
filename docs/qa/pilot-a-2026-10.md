# QA pass: Pilot A, October 2026

Scope: the three pieces built for Pilot A on 17 October 2026, tested before the
pilot uses them. CW-061 (scanner import), CW-089 (accountant export, filed-total
check, parallel run) and CW-062 (NAS installer). Written by the PO room for a
QA room that starts from nothing; read this file and `docs/handoff/QA.md`, then
only the files named here.

## Rules for this pass

- **Synthetic data only.** No file, name, ID number or amount from the pilot
  company, in the session or in the repository. Names are obviously made up
  (`ทดสอบ หนึ่ง`, `Test Two`); ID numbers come from the demo seed or are invalid
  on purpose.
- **No real NAS.** CW-062 is tested on the room's own Docker host, the way the
  dev's rehearsal was (`docs/nas-rehearsal-2026-10.md`). Nothing connects to the
  pilot's network.
- **Report, don't fix.** Each failure is a GitHub issue with steps, expected,
  actual and the synthetic input that shows it (attach the generator, not real
  files). A security problem is not an issue: write it up for the PO, who drafts
  an advisory for the owner to file.
- Each case gets **Pass**, **Fail** (with issue number) or **Blocked** (why) in
  the results table at the end of this file. Blocked is an honest answer.

## CW-061 · Scanner import

The file is UTF-16LE with a byte-order mark, tab-separated, no header, one line
per scanner number and day: name, number, date `dd/mm/yyyy` (Gregorian), times
separated by spaces, an empty fifth field; each field ends in spaces and a comma.
Build files with a small script (the spec's helpers show the exact shape).

| # | Input (synthetic) | Expected |
|---|---|---|
| S1 | A month for three registered numbers, every working day two times | Preview: no problems, all days counted; import adds them; the review page shows nothing waiting |
| S2 | A day with no time | Not counted, not waiting, not an error |
| S3 | A day with one time | Waiting for HR, reason shown; not counted until decided |
| S4 | A day with three times, and one with five | Waiting for HR; HR picks in and out from the recorded times only; out must be after in |
| S5 | Same minute twice (`08:00 08:00 17:00`) | Read as two times: counted as a normal day |
| S6 | A number nobody has registered | Shown in the unowned-numbers card with its days; not counted; matching it to an employee counts its days at once |
| S7 | `7` and `007` on different lines | Two different numbers |
| S8 | Trailing spaces and commas, blank lines in the middle | Read correctly; row numbers in any problem count the blank lines |
| S9 | UTF-16BE with a mark; UTF-8 with a mark; no mark at all | First two read the same; the third is refused, not guessed |
| S10 | A Buddhist-era year (`03/12/2569`), an impossible date, a time `25:00` | Refused with row and column named; other problems still listed |
| S11 | A sixth field with extra content | Whole file refused (nowhere to keep a template) |
| S12 | The same number and day on two lines | Flagged |
| S13 | Import S1, then a file that overlaps it with one extra time on a decided day | Nothing duplicated; that day's decision lapses and it waits again |
| S14 | Decide a day, then change the decision with the filter | Counts update each time; audit log has each decision; raw times unchanged |
| S15 | A day already used by an approved payroll run | Cannot be changed; says payroll used it |
| S16 | A user who sees only some departments | Cannot import |
| S17 | An empty file; a file of blank lines | "Empty", not a crash |

## CW-089 · Accountant export, filed-total check, parallel run

Set-up: the demo organisation, or a fresh one with four synthetic employees on
September 2026: monthly ฿12,000, monthly ฿30,000 (above the 2026 social
security ceiling of ฿17,500, so its employee share is ฿875.00), a daily-wage
worker, and one with no tax ID and no national ID. Approve the run.

| # | Action | Expected |
|---|---|---|
| P1 | Export for the accountant on an approved period | CSV opens in Excel (Thai readable); every column of the normal CSV plus Tax ID and Income type `40(1)` |
| P2 | Same on a PAID period; on a draft period | Paid exports; draft refused with the reason |
| P3 | Employee with no tax ID but a national ID; with neither | National ID used; blank |
| P4 | Audit log after an export | One entry with a row count and no ID numbers |
| P5 | Filed totals equal to Cwork's | Both shown as matching |
| P6 | Filed tax 0.01 more than Cwork's; SSO ฿100 less | Both shown as not matching, difference = filed − Cwork (+0.01, −100.00) |
| P7 | `1,250.00` with a comma; only one of the two totals; letters | Comma accepted; one total is enough; letters refused |
| P8 | Parallel-run file matching every slip | No differences |
| P9 | One person's tax 1 satang off; one person only in the file; one only in Cwork | Each flagged with the column and the difference in satang |
| P10 | A blank cell; a non-number; a missing column | Row and column named; nothing compared until fixed |
| P11 | A person paid in two runs in the period | Summed before comparing |
| P12 | After any parallel run | No slip changed (compare the slips before and after) |
| P13 | A user without `payroll:export` | Cannot export or open the check |

container on another port as the stand-in for Odoo. The real Dockerfiles cannot
be built in a cloud room; use the stand-in images the rehearsal describes, and
say so in the results.

| N9 | `rollback.sh` after an update | Previous version back, data intact |
| N10 | Path C (`--mode db`, `--mode app`) on one host | Database published on the given address only; app works through it; backups split as documented |
