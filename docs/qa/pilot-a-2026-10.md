# QA pass: Pilot A, October 2026

Scope: the three pieces built for Pilot A on 17 October 2026, tested before the
pilot uses them. CW-061 (scanner import), CW-089 (accountant export, filed-total
check, parallel run) and CW-062 (NAS installer). Written by the PO room for a
QA room that starts from nothing; read this file and `docs/handoff/QA.md`, then
only the files named here.

## Rules for this pass

- **Synthetic data only.** No file, name, ID number or amount from the pilot
  company, in the session or in the repository. Names are obviously made up
  (`ทดสอบ หนึ่ง`, `Test Two`); ID numbers come from the demo seed or are invalid
  on purpose.
- **No real NAS.** CW-062 is tested on the room's own Docker host, the way the
  dev's rehearsal was (`docs/nas-rehearsal-2026-10.md`). Nothing connects to the
  pilot's network.
- **Report, don't fix.** Each failure is a GitHub issue with steps, expected,
  actual and the synthetic input that shows it (attach the generator, not real
  files). A security problem is not an issue: write it up for the PO, who drafts
  an advisory for the owner to file.
- Each case gets **Pass**, **Fail** (with issue number) or **Blocked** (why) in
  the results table at the end of this file. Blocked is an honest answer.

## CW-061 · Scanner import

The file is UTF-16LE with a byte-order mark, tab-separated, no header, one line
per scanner number and day: name, number, date `dd/mm/yyyy` (Gregorian), times
separated by spaces, an empty fifth field; each field ends in spaces and a comma.
Build files with a small script (the spec's helpers show the exact shape).

## How the pass was run

- CW-061 and CW-089: the API from `backend` (built, `node dist/main.js`) on PostgreSQL 16 with pgvector, the demo seed, plus four synthetic employees (QA-001..004). Files were made by a script outside the repository (UTF-16LE lines in the shape of `scannerLine`). The console check for P7 ran in Chromium against the built console.
- CW-062: **stand-in images**, as in the rehearsal. The real Dockerfiles could not be built: the session's egress proxy refuses `deb.debian.org` (403), so `apt-get` fails. The stand-ins copy the host-compiled output into `node:22-bookworm-slim` (libssl borrowed from the pgvector image, uploads folder owned by the API user, health check with node instead of curl); web is the nginx stage with the built console; Docker Hub throttled some pulls so base images came through `mirror.gcr.io`. Images were saved to `images.tar.gz` and installed the way a NAS without internet would. Odoo was an nginx container on 8069. The "USB drive" was a tmpfs. Not covered: DSM, Windows trusting the authority, a scan from another machine, two real machines for path C, the real image builds, and every Dockerfile edit (uploads folder, psql in tools).
- Also checked, no problem: punch times are stored as Bangkok time (08:00 → 01:00 UTC), binding a number to a second employee or a second number to one employee is refused, 20,000 lines import in about five seconds and 20,001 is refused.
